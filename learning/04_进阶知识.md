## 4.1 模块和包 —— 代码的"收纳术"

### 4.1.1 什么是模块？

一个 `.py` 文件就是一个**模块**。

项目里的模块：
- `config.py` —— 配置模块
- `main.py` —— 主程序模块
- `data_cleaner.py` —— 数据清洗模块

**为什么要把代码拆成多个文件？**

想象你的衣柜：如果所有衣服都堆在一个抽屉里，找起来很麻烦。按类型分开放（上衣、裤子、袜子），就整洁多了。

代码也是一样：按功能拆分成模块，好找、好维护。

### 4.1.2 导入模块

用 `import` 关键字导入别人写好的代码。

```python
# 方式1：导入整个模块
import math
print(math.sqrt(16))   # 4.0

# 方式2：从模块导入特定内容
from math import sqrt, pi
print(sqrt(16))        # 4.0
print(pi)              # 3.14159...

# 方式3：起别名（常用！）
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
```

**项目中的导入**（[classifier.py](file:///workspace/machine_learning/classifier.py)）：
```python
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score
```

### 4.1.3 什么是包？

一个**文件夹**（包含 `__init__.py` 文件）就是一个**包**。

```
data_processing/        ← 包（文件夹）
├── __init__.py        ← 包的标志文件（告诉Python这是包）
├── fasta_reader.py    ← 模块
└── data_cleaner.py    ← 模块
```

**从包导入模块**：
```python
from data_processing.data_cleaner import DataCleaner

# 分解：
# data_processing  = 包名（文件夹名）
# data_cleaner     = 模块名（文件名，不含.py）
# DataCleaner      = 类名
```

**项目中的包结构**：
```

│   ├── fasta_reader.py

```

### 4.1.4 __init__.py 的作用

`__init__.py` 是包的"身份证"。有这个文件，Python 才知道这是一个包。

`__init__.py` 可以为空，也可以写初始化代码。

```python
# utils/__init__.py
# 可以为空，或者写：
from .helpers import ensure_directory, save_json
# 这样导入 utils 包时，会自动导入这些函数
```

## 4.2 异常处理 —— 程序出错了怎么办？

### 4.2.1 为什么要处理异常？

程序运行中可能遇到各种意外：
- 文件不存在
- 网络断开
- 用户输入错误
- 数据格式不对

如果不处理，程序会**崩溃**（直接退出），用户体验很差。

### 4.2.2 try-except 基本语法

```python
try:
    # 可能出错的代码
    result = 10 / 0
except:
    # 出错了怎么办
    print("除以零了！")
```

**执行流程**：
1. 先执行 `try` 里的代码
2. 如果没出错，跳过 `except`
3. 如果出错了，跳到 `except` 里执行

### 4.2.3 捕获特定异常

```python
try:
    f = open("data.csv")
    content = f.read()
except FileNotFoundError:
    print("文件不存在！")
except PermissionError:
    print("没有权限读取！")
except Exception as e:
    print(f"其他错误: {e}")
```

**常见异常类型**：
| 异常类型 | 触发条件 |
|---------|---------|
| `FileNotFoundError` | 文件不存在 |
| `ValueError` | 值的类型对，但内容不对 |
| `TypeError` | 类型不匹配 |
| `IndexError` | 列表索引越界 |
| `KeyError` | 字典中不存在这个键 |
| `ZeroDivisionError` | 除以零 |
| `Exception` | 所有异常的基类（"万能捕获"） |

### 4.2.4 finally

不管出不出错，`finally` 里的代码**一定执行**。

```python
try:
    f = open("data.txt")
    content = f.read()
except FileNotFoundError:
    print("文件不存在")
finally:
    f.close()   # 不管成不成功，文件都要关闭
```

### 4.2.5 项目中的异常处理

```python
# differential.py
try:
    self.data = pd.read_csv(expression_file, index_col=0)
    self.logger.info(f"成功读取表达数据: {self.data.shape}")
except Exception as e:
    self.logger.error(f"读取表达数据失败: {e}")
    raise   # 重新抛出，让上层处理
```

```python
# classifier.py
try:
    X_scaled = self.scaler.fit_transform(X)
    # ... 训练代码 ...
except Exception as e:
    self.logger.error(f"训练失败: {e}")
    return {'error': str(e)}
```

**异常处理的最佳实践**：
1. 只捕获你预期可能发生的异常
2. 捕获后要有处理（记录日志、返回默认值、重新抛出等）
3. 不要静默吞掉异常（出问题了装作没事）

## 4.3 类型提示 —— 代码的"说明书"

### 4.3.1 什么是类型提示？

代码里参数后面有 `: str`、`: int`，返回值前有 `->`，这就是类型提示。

```python
def greet(name: str) -> str:
    """打招呼"""
    return f"你好，{name}！"
```

**类型提示的作用**：
1. **一看就懂**：函数签名告诉你该传什么类型
2. **编辑器提示**：智能补全、错误检查
3. **减少 bug**：类型不对能提前发现

⚠️ **注意**：类型提示**不影响程序运行**，纯给人和工具看的。

### 4.3.2 常见类型提示

```python
from typing import List, Dict, Optional, Tuple

# 基本类型
def add(a: int, b: int) -> int:
    return a + b

# 列表：List[元素类型]
def sum_list(numbers: List[int]) -> int:
    return sum(numbers)

# 字典：Dict[键类型, 值类型]
def get_score(student: Dict[str, int]) -> int:
    return student["score"]

# 可选：Optional[类型] = 可以是该类型或 None
def find_user(id: int) -> Optional[str]:
    # 找到了返回名字，找不到返回 None
    pass

# 元组：Tuple[类型1, 类型2, ...]
def get_point() -> Tuple[int, int]:
    return (10, 20)
```

### 4.3.3 项目中的类型提示

```python
# differential.py
def _perform_ttest(self, group1: pd.Series,
                   group2: pd.Series) -> Tuple[float, float]:
    """执行t检验，返回(t统计量, p值)"""
    ...

# config.py
def validate(self) -> bool:
    """验证配置，返回True/False"""
    ...

def save_to_file(self, filepath: str) -> None:
    """保存配置，不返回"""
    ...
```

## 4.4 装饰器 —— 给函数"穿衣服"

### 4.4.1 什么是装饰器？

装饰器是**给函数或类增加额外功能**，但不修改原代码。

就像给手机套个壳：手机还是手机，但多了保护。

### 4.4.2 @dataclass 装饰器

项目中最常用的装饰器，在 [config.py](file:///workspace/config.py) 中：

```python
from dataclasses import dataclass

@dataclass
class AnalysisConfig:
    fasta_file: str = "data/simulated_genes.fasta"
    p_value_threshold: float = 0.05
    n_estimators: int = 100
```

**没有 @dataclass 时，要写很多代码**：
```python
class AnalysisConfig:
    def __init__(self, fasta_file="data/...", p_value_threshold=0.05, ...):
        self.fasta_file = fasta_file
        self.p_value_threshold = p_value_threshold
        ...
    
    def __repr__(self):
        return f"AnalysisConfig(fasta_file={self.fasta_file}, ...)"
    
    def __eq__(self, other):
        return self.fasta_file == other.fasta_file and ...
```

**@dataclass 自动帮你生成**：
- `__init__()` —— 初始化
- `__repr__()` —— 打印显示
- `__eq__()` —— 比较相等

代码简洁了很多！

### 4.4.3 @classmethod 装饰器

在 [config.py](file:///workspace/config.py) 中：

```python
class AnalysisConfig:
    
    @classmethod
    def load_from_file(cls, filepath: str) -> 'AnalysisConfig':
        """从文件加载配置（类方法）"""
        config = cls()   # cls 就是类本身
        # 读取文件...
        return config
```

**普通方法 vs 类方法**：

| | 普通方法 | 类方法 |
|---|---------|--------|
| 装饰器 | 无 | `@classmethod` |
| 第一个参数 | `self`（对象） | `cls`（类本身） |
| 调用方式 | `对象.方法()` | `类名.方法()` |
| 用途 | 操作对象的数据 | 创建对象、类级别的操作 |

**使用对比**：
```python
# 普通方法：先创建对象
config = AnalysisConfig()
config.validate()

# 类方法：直接用类名调用
config = AnalysisConfig.load_from_file("config.txt")
```

## 4.5 日志系统 —— 比 print 更专业

### 4.5.1 为什么不用 print？

| | print | logging |
|---|-------|---------|
| 级别控制 | 不能 | 可以（只显示INFO以上） |
| 输出到文件 | 麻烦 | 一行配置 |
| 记录时间 | 手动 | 自动 |
| 记录模块名 | 手动 | 自动 |
| 生产环境 | 不推荐 | 标准做法 |

### 4.5.2 基本用法

```python
import logging

# 获取日志记录器
logger = logging.getLogger(__name__)

# 不同级别的日志
logger.debug("调试信息")      # 最详细，开发时用
logger.info("普通信息")       # 正常运行信息
logger.warning("警告")        # 需要注意但不是错误
logger.error("错误")          # 出错了
logger.critical("严重错误")   # 程序可能要崩溃
```

### 4.5.3 项目中的日志

```python
# 几乎每个类都有
self.logger = logging.getLogger(__name__)

# 记录信息
self.logger.info(f"成功读取表达数据: {self.data.shape}")
self.logger.warning(f"样本类别不平衡，不使用分层抽样")
self.logger.error(f"读取表达数据失败: {e}")
```

## 4.6 命名规范和代码风格

### 4.6.1 命名规范

| 类型 | 规范 | 例子 |
|------|------|------|
| 变量/函数 | 小写+下划线 | `gene_count`, `calculate_gc` |
| 类 | 大驼峰 | `DataCleaner`, `DiffExpAnalyzer` |
| 常量 | 全大写 | `MAX_ITERATIONS = 100` |
| 私有方法 | 下划线开头 | `_perform_ttest()` |

### 4.6.2 写注释的原则

```python
def calculate_gc_content(self):
    """
    计算每条序列的GC含量
    
    GC含量 = (G数量 + C数量) / 总碱基数 × 100%
    
    Returns:
        List[float]: 每条序列的GC含量百分比
    """
    ...
```

- 函数要有文档字符串（说明做什么、参数、返回值）
- 复杂逻辑要加行注释
- 不要写和代码重复的注释

### 4.6.3 代码长度控制

- 一个函数最好**不超过50行**
- 一个文件最好**不超过500行**
- 太长了就拆分
